# PROJECTOR REAL-WORK OBSERVATION 004 — PRODUCT REFRAME — 2026-08-22

## Human observation

> „Projektor nie ma być projektem do budowania, tylko projektem który ma pracować.”

The Human described this as a major thinking switch: the previous framing implicitly treated Projektor as an object that must be continuously developed, while the new framing treats Projektor as an operational capability that should perform real work and only return to development when real work exposes a measured blocker.

## Why this matters

This is not merely wording. It changes the default loop from:

```text
PROJECTOR
→ BUILD
→ TEST
→ IMPROVE
→ BUILD MORE
```

to:

```text
HUMAN GOAL
→ PROJECTOR WORKS
→ REAL-WORLD OUTCOME
→ OBSERVE FRICTION
→ ONLY IF MEASURED BLOCKER: MINIMUM REPAIR
→ RETURN TO WORK
```

## Product implication

```text
PROJECTOR IS NOT THE CURRENT WORK OBJECT.
PROJECTOR IS THE WORKING MECHANISM.
```

Development is subordinate to work. It is maintenance / bounded repair triggered by evidence, not the default activity.

## Relationship to existing canon

This observation strongly aligns with the already accepted real-work-first direction:

- `REAL HUMAN PROBLEM → USE ONLY WHAT NATURALLY HELPS → OBSERVE FRICTION`
- `FINDING != TASK`
- no new architecture before measured blocker;
- one real Human job with the ecosystem AS-IS.

It does **not** itself authorize a new component, runtime, architecture change, or product expansion.

## Strong user outcome signal

The Human reported that since introducing the anti-drift / delivery rules, more was completed in roughly one week than in the prior year.

Classification:

```text
OBSERVED BY HUMAN = YES
CAUSAL ATTRIBUTION = NOT PROVEN
SIGNAL STRENGTH = HIGH SUBJECTIVE / REAL-WORLD
POSSIBLE MECHANISM = LOWER COGNITIVE INTEGRATION / COORDINATION TAX
```

The working hypothesis is that value may come less from making AI do more things and more from preventing work, decisions, and context from being lost to drift, re-navigation, and repeated reconstruction.

## Operational rule

```text
DEFAULT:
USE PROJECTOR TO DO REAL WORK.

DO NOT:
RETURN TO BUILD MODE JUST BECAUSE AN IDEA, FEATURE, OR TEST APPEARS.

RETURN TO DEVELOPMENT ONLY WHEN:
REAL WORK PRODUCES A REPEATED / MEASURED BLOCKER
OR THE HUMAN EXPLICITLY CHANGES PRODUCT DIRECTION.
```

This remains a humorous shorthand for `PARKING + RETURN CONDITION`, not a formal authority rule.
