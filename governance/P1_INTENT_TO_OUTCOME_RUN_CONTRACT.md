# P1 INTENT-TO-OUTCOME PRIMARY RUN CONTRACT

Status: `ACTIVE CURRENT-PRIORITY CONTRACT / SPECIFICATION ONLY`
Decision date: 2026-08-25

CAPABILITY CLAIM: CAP-ITO-001

## Purpose

P1 tests whether the current Human-AI ecosystem can take a rough Human intent and preserve intelligent progress until a real, effect-based DONE is reached, without forcing the work through a predetermined architecture.

Target experience:

```text
ROUGH HUMAN INTENT
-> bind the real target
-> identify the current critical unknown
-> research / create / execute what naturally helps
-> observe evidence
-> update state
-> re-route when evidence changes the path
-> stop only at genuine Human authority / normative gates
-> REAL DONE
```

This is the Projector / Intent-to-Outcome direction as a capability target, not authorization for a Projector runtime, master router, scheduler, multi-agent layer or new autonomous component.

## Valid input

The Human may begin with an unstructured thought. The Human is not required to select a tool, architecture, repository, workflow or ecosystem component.

The system is responsible for translating that thought into a bounded current target while preserving the original Human intent.

## Human ownership

Human owns:
- goal and normative meaning;
- global priority;
- run-specific DONE acceptance;
- costly, public, destructive, irreversible or materially risky authority;
- product choices that genuinely require preference rather than evidence.

## System responsibility

Using the ecosystem AS-IS, Intelligence should:
- preserve the Human goal;
- maintain the current state and one current critical unknown;
- choose the next evidence-seeking or productive move;
- perform reversible research and execution when naturally useful;
- use existing components only when the real task creates a need for them;
- record material evidence and state changes;
- re-route when new evidence invalidates the current path;
- surface a Human gate only when Human authority or normative judgment is actually required;
- never treat architecture production as task progress.

## Run freeze before material build

Before material implementation or consequential execution, record:

```text
RAW HUMAN INTENT:
GOAL:
DONE: an observable effect, not a code/document milestone
VERIFICATION: how DONE will be checked
CURRENT CRITICAL UNKNOWN:
KNOWN HUMAN AUTHORITY GATES:
```

DONE must not be defined as:
- architecture completed;
- modules created;
- interfaces defined;
- repository scaffolded;
- README/documentation finished;
- agent/router/runtime implemented without behavior proof.

## Behavior-first law

All implementation during the run is governed by `governance/BEHAVIOR_FIRST_CAPABILITY_POLICY.md`.

Required sequence for a new mechanism:

```text
real task or failing case
-> observed pressure
-> smallest working vertical slice
-> executable proof including failure path
-> repeated use if abstraction is proposed
-> refactor only after evidence
```

## Observation record

The run should preserve, when they occur:
- material state transitions;
- evidence-driven route revisions;
- disconfirmed local hypotheses;
- continuity breaks;
- Human rescue events where Human had to tell the system what operational step to take rather than make a genuine Human-owned decision;
- real authority gates;
- executable or external proof of DONE.

These are observations, not automatic architecture tasks.

## Completion condition

P1 completes only when one genuine Human project reaches its run-specific effect-based DONE with observable verification.

A useful partial result is `PARTIAL`, not DONE.

The current target capability `CAP-ITO-001` must not be promoted merely because this contract exists or because a project repository becomes architecturally complete.

## Conway Automaton reference boundary

`Conway-Research/automaton` may be used ex post as a reference class for product completeness.

It is not an architecture checklist.

During development ask:

```text
What does this real product require?
```

Do not ask:

```text
What does Automaton have that we have not built yet?
```

## No forced ecosystem path

```text
REAL HUMAN PROBLEM
-> USE ONLY WHAT NATURALLY HELPS
-> OBSERVE FRICTION
```

No component usage quota exists. Base Intelligence alone may be correct for a step. A component enters only under measured pressure from the current real task.
